# Shared showcase authoring and sessions

`@flowsvg/showcase` is a workspace-only package that consumes the SDK. It is never an SDK dependency. The formal catalog in [src/formal.ts](src/formal.ts) selects **Basic shapes: complete catalog** (`basic-shapes`) as its first and default example. It is followed by **Request and response** (`request-response`) and **RAG: From sources to answers** (`rag-workflow`). Complete author definitions live in [basic-shapes](src/examples/basic-shapes.ts), [request-response](src/examples/request-response.ts), [rag-workflow](src/examples/rag-workflow.ts), [project-architecture](src/examples/project-architecture.ts), [vllm-metal-stack](src/examples/vllm-metal-stack.ts), [job-lifecycle](src/examples/job-lifecycle.ts), [order-event-pipeline](src/examples/order-event-pipeline.ts), [web-service-deployment](src/examples/web-service-deployment.ts), [cache-aside-sequence](src/examples/cache-aside-sequence.ts), and [llm-inference](src/examples/llm-inference.ts). [src/acceptance.ts](src/acceptance.ts) is an explicit mechanism-acceptance input; it never fills the formal catalog.

TypeScript is the only author source. Each source module exports `catalogSource` with definitions, an explicit ordered ID list, and `defaultId`. Each definition supplies an ID, name, primary `category`, introduction, complete diagram document, and complete `speed`, `theme` and `reducedMotion` defaults. IDs use lowercase letters, digits and single hyphens. Compose variants in TypeScript; each selected variant must contain a complete document before generation.

Each definition selects one primary category from [src/categories.ts](src/categories.ts). `catalog.groups` exposes populated categories in the order in which they first appear in `catalog.entries`. Each group retains its entries' relative catalog order. Grouping does not choose the default example. Hosts render the shared groups with accessible headings; empty categories have no placeholder or disabled control. Category metadata stays outside standalone diagram JSON.

| Category ID | Navigation label | Purpose |
| --- | --- | --- |
| `architecture` | Architecture | Components, responsibilities and layers |
| `workflow` | Workflow | Task steps and decisions |
| `sequence` | Sequence | Ordered communication between participants |
| `data-flow` | Data flow | Data sources, transformations and destinations |
| `state` | State transitions | States and triggering events |
| `deployment` | Deployment | Runtime locations and connections |

The formal navigation fills all six categories, in this order: workflow, architecture, state, data-flow, deployment and sequence. See [src/formal.ts](src/formal.ts) for the selected stories and their order; each author definition supplies its category. The isolated signal acceptance definitions use `data-flow`.

All public story text, category labels and generated diagram documents use English. Keep stable IDs when editing wording so example links remain valid.

The SDK Loop button starts off. Its choice survives example, theme, reduced-motion, retry, Back/Forward and persisted page-cache replacements in the current page session. The host captures loop with time and speed only at operations; the SDK owns the playback clock. Fresh entry or refresh starts with looping off. Loop is absent from share URLs and downloaded diagram JSON, and does not configure GIF repetition.

## Additional diagram purposes

Playback durations come from SDK `totalDuration` after compilation. Each single-flow beat replaces its authored duration with movement plus a 500 ms post-arrival interval.

For a single flow, the sender paints immediately. After arrival, the receiver fill and stroke fade in over 200 ms. Automatic node and edge highlights then stay fully painted for 100 ms and fade out over 200 ms before the beat ends. Reverse flows swap sender and receiver. Logical `highlighted` flags and markers last for the whole beat; content, geometry and explicit actions retain their authored timing. Explicit highlights take precedence, and `highlightParticipants: false` disables automatic endpoint paint. Reduced motion skips both fades while preserving the 500 ms post-arrival interval. Multiple flows retain their existing synchronized timing and paint. Player speed scales the fades with the timeline; SVG and export evaluate the same colors.

## Prepare and generate

From the repository root:

```sh
pnpm install
pnpm build
pnpm --filter @flowsvg/showcase build
pnpm --filter @flowsvg/showcase typecheck
pnpm --filter @flowsvg/showcase test
```

The SDK must be built first. The package build compiles TypeScript to JavaScript and declarations, then generates catalog data and JSON. Changes to author definitions require rebuilding this package and the consuming app. Changes to the SDK require rebuilding the SDK first. No watch process is implied by these commands.

For the isolated acceptance catalog:

```sh
SHOWCASE_SOURCE=dist/acceptance.js pnpm --filter @flowsvg/showcase build
```

Use `SHOWCASE_SOURCE=dist/acceptance-empty.js` for an explicit empty catalog. Empty-state checks do not depend on the formal selection.

`SHOWCASE_SOURCE` selects a compiled author module relative to this package directory; the default is `dist/formal.js`. Normal app dev/build commands regenerate the default formal catalog unless the caller explicitly selects a different source. A previous acceptance build cannot silently select formal content.

## Consumption and output

`@flowsvg/showcase/author` exports `catalog`: immutable ordered `entries`, `defaultId`, and `get(id)`. Unknown IDs return `undefined`. Definitions include complete defaults, SDK-derived `durationMs`, and a site-relative `jsonPath`. Empty catalogs have no entries and a null default. The browser entry imports no SDK runtime, player, DOM or framework code. SDK document types are type-only references.

`@flowsvg/showcase/build` exports `compileCatalog(input)`. This build-time interface validates author input and returns the same catalog plus a map of standalone JSON documents. Errors identify the author field or example ID and SDK field path. Generation rejects duplicate/missing IDs, unlisted definitions, invalid defaults, lossy JSON values and SDK document errors before replacing generated site data. Functions, undefined values, nonfinite numbers, circular references, sparse arrays, accessors and custom objects are not JSON data. Duration comes from SDK compilation, including zero for a static diagram.

The build emits JavaScript and declarations in `dist/`. `dist/site/json/<id>.json` contains diagram documents only: no introduction, defaults or duration metadata. Each app's Vite build copies `dist/site/` into its independent site. Generated files are ignored by Git and must not be edited as a second author source.

`tests/compact-layout.test.ts` checks viewport budgets, no content overflow at every beat boundary and at most 24 unused safe-area units below content. RAG checks apply at every current stage; other stories retain stable geometry and a fullest-content budget. Task-state checks use complete line boxes and tag backgrounds. `tests/job-lifecycle.test.ts` also checks initial inactive content, all nine stage starts and midpoints, nonmonotonic seeks, both themes and reduced motion. Common real-host and delivery checks exercise task playback, pause/resume and seeking while comparing SVG card geometry. Common host checks also verify compact RAG initial cards, stage expansion, row gaps, fitted canvas height and restoration after backward seeking.

The public author/build interfaces and generated JSON are exercised by `tests/author.test.ts`. `tests/formal.test.ts` checks formal ordering/default selection and generated documents. `tests/rag-workflow.test.ts` checks visible candidate/selection/citation labels, question and retrieval flows, eight stage boundaries, both themes, reduced motion, compact layout, fitted canvas heights and SVG viewBoxes at exact stage boundaries and backward seeks, distinct input tips, cardinal arrival tangents and every active transfer against node interiors. `tests/project-architecture.test.ts` checks rounded orthogonal routes, architecture semantics, six stage boundaries, both themes, reduced motion and transfer clearance. `tests/vllm-metal-stack.test.ts` checks four-layer ordering, real nested containment, reference responsibilities and optional conditions, group-boundary transfers, themes/motion and transfer clearance. `tests/category-examples.test.ts` checks the four additional purposes, current-state uniqueness, event conservation, nested deployment roles, ordered response directions and separated state-event labels. `tests/compact-layout.test.ts` defines the stories covered by the structured-content and viewport-budget checks. `tests/basic-shapes.test.ts` checks measured preset labels, horizontal row connections and compact group/viewport bounds through playback and label replacement. ## Presentation sessions

`@flowsvg/showcase/session` exports `createSession(catalog)` and `transitionSession(catalog, current, operation, snapshot?, address?)`. This browser-safe entry uses only pure address helpers and type imports. It does not depend on the author entry, DOM, frameworks, global locations, players or clocks. The author entry does not depend on it.

A session holds `exampleId`, complete `settings`, target `timeMs`, runtime `loop`, monotonic `version` and parameter `diagnostics`. Empty catalogs have a null ID and null settings. A snapshot contains the SDK's action-time `timeMs`, `speed` and `loop`; hosts read these values when handling an operation instead of mirroring playback frames.

Operations select an example, change theme, change reduced motion or retry the saved selection. Selection resets time and adopts the target's default speed while retaining current visual choices. Visual changes preserve snapshot time/speed/loop; without a mounted player they use the saved target. Unchanged/unknown choices return `replacePlayer: false`. Retry gives the same target a fresh resource version, including after a cached page resumes.

A transition with `replacePlayer: true` requires the host to invalidate old callbacks, pause and destroy/unmount the old player, then mount the new version with its loop choice, apply speed and time and leave it paused. Hosts own errors, subscriptions and cancellation. The shared module never advances playback or copies frame state. `tests/session.test.ts` verifies these public operation results alongside the author interface tests.

## Shareable addresses and history

The same session entry exports `restoreSession(catalog, address, version?)` and `serializeSession(address, session)`. The caller supplies an address string; the module never reads global browser state. Restore uses the target example's default speed and missing visual defaults, clamps time with generated duration, and returns a paused mount target. Diagnostics identify each invalid field and survive canonical replacement. Empty catalogs never invent an example ID.

Known query fields are `example`, `theme`, `reduced` and `time`. Theme is `light` or `dark`; reduced motion is `0` or `1`. Time is milliseconds with grammar `digits` or `digits.digits`: no empty values, spaces, signs, exponents, hex or nonfinite values. Leading zeros are accepted and normalized. Duplicate known fields invalidate that field, including encoded spellings of the same name. Invalid fields use the target example's defaults, or zero for time; unknown IDs use the explicit catalog default. Finite time beyond duration clamps to the end; static diagrams restore zero. Serialization expands small fractional numbers into decimal spelling so links round-trip without exponents. Unrelated raw query tokens, their order/encoding, deployment path and fragment are preserved. No speed, loop or playing state is added to addresses.

`SessionTransition.addressUpdates` is an ordered list of host effects. Selection/visual changes first replace the old history entry with the action-time snapshot and then push the target. Same-value choices and retries do not write history. A `share` operation returns `copyAddress` and one replacement with its captured snapshot; `replacePlayer` is false and the resource version is unchanged. A `restore` operation parses its address, increments the resource version and never pushes. Initial restore canonicalizes with replace only and starts with loop off. A history `restore` retains the current operation snapshot's loop choice, or the saved session choice when no player is available.

Hosts execute these effects in order and own history listeners and clipboard work. Share copies the captured full address after replacement without pausing or rebuilding the player. Clipboard failure must expose a manual-copy address. A stale clipboard result must not affect a later share, presentation version or exited page. Playback, seek, scenes, beats and speed changes alone do not write addresses. Back/Forward recovers the last saved snapshot of each entry; it does not promise an unsaved final playback instant. `tests/address.test.ts` verifies the shared address/operation interface; the native built-site suite verifies actual clipboard/history integration.

Use `Diagram.beats` for scene links and time sampling. Do not sum authored `durationMs`: a single transfer replaces authored beat timing with movement plus a 500 ms post-arrival interval. Catalog `durationMs` comes from SDK `totalDuration`; introductions omit fixed duration claims.
