# 可序列化强调配色与独立连线着色策略

Status: accepted

本决策于 2026-11-12 确认。公开配置见 [SDK 指南的主题与无障碍说明](../guides/sdk-guide.zh-CN.md#主题与无障碍)；行为与安装包验收见 [SDK 验证说明](../verification/sdk-verification.md)。

图解作者需要保留关系颜色语义并选择强调配色。仅由宿主提供配色会使图解 JSON 无法单独保存作者意图，仅由文档提供配色又会限制宿主的展示选择。因此，强调配色同时由图解文档保存作者默认值，并允许运行时视觉选项逐项覆盖。每种颜色按“运行时已提供值、文档已提供值、当前主题默认值”的顺序解析；明确配置的颜色不随主题切换而改变。

强调配色覆盖节点高亮填充、节点与连线高亮描边及传递标记底色、传递标记文字。显式高亮、flow 自动着色和浏览器节点悬停共用解析后的强调配色。悬停仍只属于浏览器交互，不写入核心画面或导出结果；默认仅改变描边，启用 hoverFill 才改变填充。普通主题颜色继续由现有主题和作者普通样式决定。

公开类型 EmphasisColors 使用可选的 fill、stroke、markerText 字段；图解文档与运行时选项均通过 emphasis 对象接收。该合同覆盖核心求值、SVG、浏览器及框架宿主、PNG、GIF、离线 HTML 和播放器内 GIF 导出。Web Component 通过对象属性接收运行时覆盖；CLI 仅消费文档配色，运行时配色覆盖由程序 API 接收。

每次 flow 通过可选布尔值 highlightEdge 独立控制连线自动着色，默认 true。该策略不取消显式高亮、不阻止普通样式更新，也不改变端点自动高亮策略或 flow 的逻辑活跃状态。减少动画继续隐藏传递标记并尊重作者关闭的自动着色，即使组合后没有自动可见提示，也不新增静态提示。

这项扩展保留 [ADR 0003](0003-consistent-visual-options.md) 的可序列化视觉选项、跨渲染结果一致和普通样式与高亮分层原则。它扩展 [ADR 0002](0002-continuous-global-timeline.md) 中默认连线自动着色的设计，未配置时仍保留现有行为，编译时序不变。SDK 与创作工具继续独立集成和发布，职责见[创作工具集成约定](../development/authoring-tools.md)。
