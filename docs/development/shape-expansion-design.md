# 预置形状扩展设计

日期：2026-11-07  
状态：已在源码实现并完成 SDK 交付验证（2026-11-07）；尚未发布到 npm。

背景来自独立 `flow-svg-diagram-skills` 仓库的 `docs/development/flowsvg-shape-expansion-research.md`（2026-11-07）。本文自包含地记录 SDK 侧设计，不要求读取或安装兄弟仓库；调研与本文均不代表 SDK 已发布能力。

## 已确认的设计边界

首批围绕通用流程图的五类语义选择预置形状。新增形状及公开 `kind` 如下。

| 新增形状 | `kind` | 语义 | 典型节点标签 |
| --- | --- | --- | --- |
| 菱形 | `diamond` | 条件判断、分支 | 审核通过？ |
| 平行四边形 | `parallelogram` | 输入、输出 | 接收用户输入 |
| 文档形，底部波浪边 | `document` | 文档、报告、文件产物 | 生成评估报告 |
| 预定义流程，两侧带竖线的矩形 | `predefinedProcess` | 调用已定义的子流程 | 执行身份验证 |

开始与结束复用现有椭圆或圆角矩形，普通处理步骤使用现有矩形。云、人物、设备等架构图符号留待后续讨论。

新增的特殊形状只接受节点标签 `label`，不接受结构化节点内容 `content`。标签允许换行，使用统一字号和文字颜色，不包含标题加正文、列表、短标签或实体图内容块；详细解释由相邻说明节点承载。该边界用于控制特殊轮廓内部的排版复杂度。

每种新形状定义一个矩形内容安全区，避开尖角、斜边、波浪边或双竖线。标签在安全区内自动换行，整体水平、垂直居中，并支持显式换行。同一节点的每行可用宽度相同，不沿轮廓逐行改变宽度。

四种新形状的节点标签遵循以下溢出规则：中文正常换行，英文优先保留完整单词，单个长词或 URL 超宽时允许按字符拆行，保留完整字素；文字仍放不下时，在安全区内裁剪并报告 `text-overflow`。不自动缩字、不自动改变节点尺寸、不加省略号。节点尺寸只要求有限且严格大于零；尺寸过小导致非空标签无法排版时给出警告，不增加形状专属的最小尺寸硬错误。

首版只允许作者通过宽高调整新形状，不提供倾斜程度、波浪幅度或双竖线间距的独立配置字段。SDK 根据节点尺寸计算轮廓和安全区，具体规则见下文。

为四种新形状提供节点标签尺寸测量入口 `measureNodeLabel`，与现有 `measureNodeContent` 对应。作者提供形状、宽度与标签，测量返回容纳文字所需的建议高度及无法解决的溢出问题；多个标签版本共用一个能容纳各版本的建议高度。测量与实际排版复用规则，只返回建议，不修改图解文档或节点尺寸。

新增形状继续使用 `top`、`right`、`bottom`、`left` 四个端口方向。连线端点使用真实外轮廓；命中不包含包围矩形中形状以外的空白区域；诊断使用相同轮廓。预定义流程的内部双竖线不作为连线端点或额外障碍；其可见描边以所属节点身份参与几何诊断。形状只提供表达语义，不按形状限制连线数量，例如不强制菱形只能有两个出口。

本次安全区标签排版、裁剪策略和 `measureNodeLabel` 仅服务四种新增形状。现有形状的标签行为与测量扩展另行评估。

术语使用见根目录[术语表](../../GLOSSARY.md)：节点标签是一个整体排版的纯文本说明；节点内容是多个结构化内容块的组合。

## 轮廓与安全区

以下均为图解单位。节点局部原点为左上角，宽高分别为 `W`、`H`；文字内边距 `P = 12`。安全区宽高计算结果小于零时取零，非空标签无法容纳时按溢出规则处理。

| 形状 | 轮廓规则 | 安全区 `(x, y, width, height)` |
| --- | --- | --- |
| `diamond` | 顶点位于包围矩形的上、右、下、左四边中点；使用半宽、半高的居中内接矩形再扣内边距 | `(W/4 + P, H/4 + P, W/2 - 2P, H/2 - 2P)` |
| `parallelogram` | 顶边向右倾斜；偏移 `S = min(W/4, 24)`；顶点为 `(S,0)`、`(W,0)`、`(W-S,H)`、`(0,H)` | `(S + P, P, W - 2S - 2P, H - 2P)` |
| `document` | 顶边与两侧为直线，底部为波浪边；波浪限制在底部高度为 `B = min(H/4, 24)` 的带内 | `(P, P, W - 2P, H - B - 2P)` |
| `predefinedProcess` | 矩形外框，左右各一条竖线；竖线距对应外边框 `D = min(W/6, 12)` | `(D + P, P, W - 2D - 2P, H - 2P)` |

文档形的标签在波浪带上方的安全区内居中，因此会略高于整个节点的中心。固定轮廓参数和安全区共同用于渲染与测量。

## 标签测量契约

以下调用适用于包含本次改动的源码构建；已发布的 0.2.3 尚不包含此 API。

```ts
const measurement = measureNodeLabel({
  kind: "diamond",
  width: 200,
  label: ["通过？", "是否完成全部审核？"],
  typography: { nodeLabel: 16 }
});
// measurement: { height, diagnostics }
```

输入 `NodeLabelMeasurementInput`：

- `kind`：仅接受上述四种新增形状。
- `width`：有限且严格大于零的节点宽度。
- `label`：一个字符串，或非空的只读字符串数组；空字符串合法，每个数组元素是一个标签版本。
- `typography`：可选，使用现有 `DiagramTypography`，与图解文档的文字上下文一致。

输出 `NodeLabelMeasurement`：

- `height`：有限且严格大于零的建议节点高度，包含形状留白和完整行框；取各标签版本所需高度的最大值。
- `diagnostics`：无法通过增加高度解决的宽度问题。每项使用 `versionIndex`、`path`、`dimension: "width"` 和 `message` 标识版本、字段和原因；单字符串使用版本索引零。

安全区宽度窄到单个完整字素也放不下时，测量保留该字素作为一行估算高度并返回宽度诊断；增加高度不能消除该诊断。标签为空时不产生文字溢出诊断，建议高度仍为正数。测量不读取 DOM 字体度量、不自动扫描时间线，也不修改输入。

非法形状、非正数或非有限宽度、非法文字配置、空版本数组及非字符串标签等输入错误抛出 `DiagramValidationError`。有限输入导致高度运算结果非有限时同样抛出该错误，不返回非有限高度。

### 高度与实际排版一致

以下公式由已确认的安全区规则推导。设单个版本的标签行框总高度为 `L`，其中空标签的 `L = 0`：

- 菱形：`H = 2 × (L + 2P)`。
- 平行四边形和预定义流程：`H = L + 2P`。
- 文档形：令 `T = L + 2P`；当 `T ≤ 72` 时，`H = 4T/3`；否则 `H = T + 24`。该公式解出 `H - min(H/4, 24) = T`。

测量输出不能因数值舍入小于完整行框所需高度。若宽度诊断非空，即使采用建议高度，文字也可能被裁剪；调用方需要增加宽度或缩短标签。

## 整体验收方案

以下验收方案已随完整设计确认，尚未执行。实现时先编写行为测试并验证失败，再实现对应能力。

| 范围 | 关键验收 |
| --- | --- |
| 文档校验 | 四个新 `kind` 合法；未知 `kind` 非法；初始节点及时间线更新均拒绝新形状的结构化 `content`；尺寸非有限或非正数报错，正数极小尺寸按溢出规则处理 |
| 标签排版 | 中英文、显式换行、长词、URL、完整字素、空标签；固定矩形安全区、整体居中；过高或过宽时裁剪并给 `text-overflow`，不缩字、不改尺寸 |
| 测量 | 单标签与多版本、默认与显式字号、极窄宽度、空字符串、非法输入及高度数值溢出；采用建议高度后无高度溢出，不能解决的宽度问题保留诊断 |
| 几何 | 四方向端口；显式与自动连接；直线、正交和曲线；同侧多入线；端点、命中和诊断遵循外轮廓，双竖线不影响端点与障碍判断 |
| 集成与时间线 | 与分组及现有节点混用；标签、位置和尺寸更新；隐藏、显示、强调和样式过渡；每帧按当前尺寸计算轮廓与安全区，不增加 `kind` 动态更新能力 |
| 导出 | SVG、PNG、离线 HTML 和 GIF 复用相同轮廓、标签排版与裁剪结果；跨系统字体差异遵循既有边界 |
| 现有行为 | 保留既有形状的标签排版、内容测量和渲染行为；共享几何模块变更不能意外改变既有形状 |

实现完成时同步根目录与受影响包的 `CHANGELOG.md`、`PATTERNS.md`，审查并更新受影响的中英文 README 与 SDK 手册；示例覆盖四种形状及测量。SDK 自身完成验证后，独立 Skill 再按精确发布版本升级文档、运行时和验收，不使用私有渲染补丁提前模拟形状。

## 实施前的 SDK 基线（2026-11-07）

- 公开形状为 `rect`、`roundedRect`、`ellipse`、`cylinder`、`group`。`label` 与 `content` 互斥；`content` 仅支持矩形、圆角矩形和圆柱体。见 [model.ts](../../packages/flowsvg/src/core/model.ts) 与 [node-content.ts](../../packages/flowsvg/src/core/node-content.ts)。
- 普通节点标签按包围矩形宽度扣除内边距换行，并居中排版；目前不使用形状内接安全区。高度溢出给出警告，文字继续绘制。见 [diagram.ts](../../packages/flowsvg/src/core/diagram.ts)。
- 节点尺寸校验只要求有限且严格大于零；没有按形状设置最小尺寸的硬错误。见 [validation.ts](../../packages/flowsvg/src/core/validation.ts)。
- 实施前的连线并非在所有形状和路由组合中都精确落在真实轮廓上。例如圆柱的自动直线端点仍按包围矩形计算。上述新形状的真实轮廓连接要求属于新增契约。见 [edge-geometry.ts](../../packages/flowsvg/src/core/edge-geometry.ts)。
